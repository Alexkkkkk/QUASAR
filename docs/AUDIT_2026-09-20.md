| ID | Важность | Область | Файл | Суть |
|---|---|---|---|---|

## Применённые исправления

### F-17
```tact
receive(msg: ClaimReferralRewards) {
    ...
    require(self.reserveBalance - self._poolEncumbrance() >= pending!!, "Reserve encumbered");
    self.pendingReferralRewards.set(claimant, 0);
    self._sendTokens(claimant, pending!!, 0, myAddress());
}
```
Приводит реферальный клейм к тому же правилу свободного резерва, что уже применяется в
трежери-ветке `FeeTransfer` и в `DefiPayout`.

### F-18
```tact
receive("Resume Minting") {
    self._requireOwner();
    require(!self.aiFullAutonomy, "AI controls");
    self.mintable = true;
}
```
Только владелец, и только пока AI не получил полную автономию. Закрывает
необратимость, при которой аварийная пауза AI навсегда сжигала возможность эмиссии.

## Тесты

`tests/audit_fixes.test.ts` (новый):
- `F-17 source` — инвариант исходника: реферальный клейм обязан содержать free-reserve guard.
- `F-18 source` — инвариант: наличие owner-only пути `"Resume Minting"` и запрет при `aiFullAutonomy`.

## Открытый дефект (не исправлен этим патчем)

**Fee-путь ревертится с exit code 5 (integer out of expected range).**
Воспроизведено диагностическим скриптом на текущем `main` @ `120656e`:
`FeeTransfer`, отправленный мастеру от Jetton-кошелька, падает до распределения
комиссий (compute phase exit=5, `reserveBalance` остаётся 0). Дефект предсуществующий
(задокументирован ещё в `docs/F09_BUYBACK_REMEDIATION.md` для коммита `d03e788`) и
блокирует любой позитивный прогон fee/buyback-путей. Требует отдельной глубокой
диагностики фаз транзакции (рекомендуется `print`-трассировка FunC и пошаговый
разбор `actionPhase`); в этом патче не затрагивался, чтобы не смешивать изменения.
