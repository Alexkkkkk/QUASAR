## 2. Findings and remediation

### A-01 (high) — unresolved TEP-64 content was immutable — issue #58

`content` is part of the master’s init data and no receiver changed it, so a
typo in the metadata URI was permanent even though the wallet-code migration
path already existed.

Remediation: `ProposeContent` / `"Cancel Content"` / `"Apply Content"` with the
same 48h `ownerTransferDelay` timelock as the wallet-code migration, an on-chain
first-byte check for the documented layouts, `get_pending_content` and
`get_content_at` for off-chain monitoring, plus the `tep64.ts` preflight helper.

Note: the pre-existing branch `feat/tep64-managed-onchain-metadata` implemented
the same feature but also deleted `docs/abi/*.json`, `scripts/check_abi.ts` and
`tests/tep89_wallet_discovery.test.ts`. Merging it as-is would have removed the
ABI gate added by issues #64/#68 and a TEP-89 regression test, so the feature was
re-implemented on top of `main` and both gates were kept.

### A-02 (medium) — TEP-89 wrong-workchain answer — issue #60

The master always replied with a computed wallet address. TEP-89 requires
`wallet_address = addr_none` when an address cannot be derived for the requested
owner, for example because it is in another workchain. The workchain is now
parsed from the raw owner slice and the address is only returned when the
computed wallet lives in the same workchain; otherwise the response carries
`addr_none$00`.

### A-03 (medium) — dApp opcodes were not machine-checked — issues #55, #61

`website/tonconnect.js` mirrors contract opcodes by hand. Nothing failed the
build when a contract opcode changed, so a stale dApp could send a message the
contract would reject. `scripts/check_dapp_abi.ts` now compares every entry of
that map with the compiled ABI, and CI runs it after the contract tests.

### A-04 (low) — off-chain helper refused a documented attribute — issue #60

`wallet-discovery` is the TEP-89 attribute a non-upgradable master uses to point
at a discovery contract. The decoder rejected unknown names, so a legitimately
encoded cell failed preflight. It is now a known attribute.

### A-05 (low) — audit trail and release notes were missing — issue #66

`docs/` carried eight per-fix remediation notes but no consolidated report and
the repository had no `CHANGELOG.md`; the README’s feature matrix and its
safeguards section described the removed veto path inconsistently. This report
and `CHANGELOG.md` were added and the README text was aligned with the code.

## 3. Not covered by this change set

- **Independent audit (#62)** still requires a third party and cannot be
  produced here. CI can now publish build-artifact hashes, but no canonical
  deployment addresses are recorded in the repository yet, so the real-funds
  readiness item stays open.
- **Property/invariant coverage (#63)** is now partially addressed by
  `tests/property_invariants.test.ts` (deterministic CPMM, LP quote and staking
  accounting coverage), but this report itself did not review an external
  deployment or fuzzing infrastructure.
- **Wallet-size limit (`maxWalletBps`)** is enforced on transfers, but a
  receiving-wallet cap is not a substitute for a contract-enforced cap; do not
  advertise one.
