# F-01 Remediation — Jetton Metadata (TEP-64)

Дата: 2026-09-20
Ветка: `fix/f01-jetton-metadata`

## Суть проблемы (F-01)

TEP-64 content ячейка минт-мастера указывала на жёстко зашитый URL:

```
https://quasar-ton.netlify.app/metadata.json
```

Фактическая проверка (2026-09-20): URL отдаёт **HTTP 404**, как и
`.../assets/logo.png`. Кошельки и эксплореры не могут отрисовать имя,
символ и логотип токена.

## Почему это было опасно

Контент-ячейка — часть init-данных контракта: она входит в адрес и
**неизменяема после деплоя** (в `QuasarMaster` нет ни owner-сеттера контента,
ни AI-сообщения для него). Зашитый мёртвый URL нельзя вылечить апгрейдом
контракта — только хостингом по этому адресу.

## Что сделано

| Файл | Изменение |
|---|---|
| `scripts/deploy_all.ts` | URL метаданных больше не зашит: читается `JETTON_METADATA_URL` (дефолт — `raw.githubusercontent.com/.../website/metadata.json`). Перед деплоем добавлен preflight: `fetch` URL + валидация обязательных полей TEP-64 (`name`, `symbol`, `decimals`, `image`). Деплой падает сразу, если метаданные недоступны |
| `.env.example` | Задокументирована переменная `JETTON_METADATA_URL` |
| `website/metadata.json` | `image` переведён с мёртвого Netlify-домена на `raw.githubusercontent.com` |
| `tests/contracts.test.ts`, `tests/security_regression.test.ts` | Контент-константы обновлены; добавлен source-инвариант F-01 (падает, если вернуть хардкод мёртвого URL или убрать preflight) |

## Почему дефолт — raw.githubusercontent.com

- анонимный доступ подтверждён (HTTP 200, без токенов);
- файл версионруется git-ом — содержимое метаданных привязано к коммиту;
- не зависит от стороннего бесплатного хостинга, который может исчезнуть
  (что и произошло с Netlify-аккаунтом).

Оговорка: `raw.githubusercontent.com` отдаёт `text/plain` вместо
`application/json`. Все известные реализации TEP-64 (tonviewer, tonscan,
Tonkeeper и т.д.) парсят тело ответа без проверки MIME, но для продакшена
рекомендуется GitHub Pages или собственный домен с корректным MIME.

## Миграция уже задеплоированного токена

Патч чинит **будущие** деплои. Если QSR уже задеплоирован в сеть,
контент-ячейку изменить нельзя. Два пути:

1. **Рекомендуется (без миграции холдеров):** переопубликовать
   `website/metadata.json` и `website/assets/logo.png` по старым адресам
   (Netlify-сайт). Существующий джеттон сразу оживает в кошельках.
2. **Редеплой нового мастера** с корректной контент-ячейкой: новый адрес,
   необходимость переносить ликвидность/пулы — только если вариант 1
   недоступен.

Примечание: на том же мёртвом домене лежит и `tonconnect-manifest.json`
(F-02-область) — если Netlify не восстанавливается, паттерн
`raw.githubusercontent.com` применим и к нему.
