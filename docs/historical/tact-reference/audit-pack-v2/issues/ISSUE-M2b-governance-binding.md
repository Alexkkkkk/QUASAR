# [Security][Medium] Governance: вес голоса не привязан к содержанию предложения (bait-and-switch)

## Описание

F-35 закрыл replay proposalId через `govProposalExecuted`, но голос по-прежнему
копит tally по одному `proposalId`, а исполняются поля `msg` (kind/flag/feeBps)
того голоса, что пересёк кворум. Голосующий «за смену fee» может непреднамеренно
дожать до исполнения паузу, если мошенник использует тот же proposalId с
другими параметрами.

## Фикс (в паке v2)

Вес голоса и tally привязаны к `hash(proposalId, kind, flag, feeBps)`;
голос записывается на хэше контента + voter. Голоса за другой контент того же
proposalId попадают в отдельную корзину и не могут исполнить неподписанное
действие. Исполнение помечает proposalId used — для всех вариантов контента.

## Критерии приёмки

- [ ] Два голоса с одинаковым proposalId, но разными kind/flag — независимые tally
- [ ] Кворум по одному контенту не исполняет другой
- [ ] Регрессия F-35: повторное исполнение того же proposalId revert'ится
