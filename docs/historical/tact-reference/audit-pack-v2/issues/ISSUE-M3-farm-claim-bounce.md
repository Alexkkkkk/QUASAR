# [Security][Medium] ClaimFarmRewards обнуляет долг до подтверждения доставки — награда сгорает при bounce

## Описание

В `contracts/quasar_defi.tact` `ClaimFarmRewards` обновляет запись фермера
(`debt = accRewardPerShare`, `pending = 0`) **до** отправки payout'а
(`_sendQsr(..., kind 2)`). Если payout отскочит, `PayoutFailed` (kind 2)
восстанавливает только `farmRewardReserve` — пользовательская запись уже
обнулена, награда остаётся в резерве и им больше не принадлежит.

Реалистичный триггер: `InternalTransfer` отклонён принимающим кошельком.
В кошельке стоит анти-китовый кап `QUASAR_MAX_WALLET_AMOUNT` (3% сапплая) —
награда + баланс > кап → revert → потеря награды.

## Предлагаемое направление

Симметрично мастеровской схеме: регистрировать farm-выплату в pending-ledger
с типом «farm reward» и восстанавливать `pending` пользователя в bounce-обработчике.
Либо проще: обнулять долг только после подтверждения доставки (подтверждение
уже приходит в DeFi — есть точка, где фиксировать факт успеха).

## Почему не в пакете фиксов

Требует выбора между двумя семантиками (ledger vs deferred-zeroing) —
design-решение. Критерий: farm-награда — обязательство протокола, bounce
не должен её уничтожать ни при каком поведении принимающей стороны.
