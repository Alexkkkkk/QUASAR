# [Security][Medium] Семантика паузы: fee-поток и автобайбэк живы в паузу, стейкинг/вестинг заморожены

## Описание

Два связанных наблюдения в `contracts/quasar.tact`:

1. `receive(msg: FeeTransfer)` не имеет `_requireNotPaused()`: во время
   emergency-паузы комиссии продолжают распределяться, treasury-платежи
   уходят, а автобайбэк внутри `FeeTransfer` может запустить AMM-своп
   при живом QuasarDeFi.
2. `Unstake`, `ClaimRewards`, `ClaimVested`, `ClaimReferralRewards` требуют
   не-паузу — весь пользовательский капитал в стейкинге/вестинге заморожен.
   После перевода owner на `QuasarAdminTimelock` (minDelay ≥ 24h) выход из
   паузы стал ≥24-часовым: окно заморозки принципиально выросло.

Дополнительно: `ToggleTrading` фактически гейтит только `Mint` — P2P-переводы
(автономные кошельки) паузу не видят. Название «Trading toggle» вводит
в заблуждение относительно фактической поверхности действия.

## Предлагаемое направление

- Решить явно: либо пауза глушит и fee-поток (кроме накопления), либо
  документировать fee-flow как не-приостанавливаемый по дизайну.
- Рассмотреть разрешение `Unstake` при паузе (вывод принципала — не усиление
  риска; QuasarDeFi уже держит RemoveLiquidity живым при паузе — выровнять).
- Переименовать/передокументировать `ToggleTrading` → `ToggleMint`.

## Почему не в пакете фиксов

Изменение экономической семантики — только через design-решение + аудит
изменения поведения (касается пользовательских средств и emission).
